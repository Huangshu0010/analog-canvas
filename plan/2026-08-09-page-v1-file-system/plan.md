# Page v1 File System

## Goal

Implement the platform-neutral foundation for the static Page editor's formal
project files, browser recovery, and deploy-safe application shell. The Page
release is a GUI-only editor: it has no Agent API, MCP surface, backend, or
server-side storage.

## Dirty-state decision

The worktree is dirty. `apps/editor/src/App.tsx` is modified by an active,
uncommitted drafting and wire-interaction target. It owns the present browser
save/recovery call sites, so this target must not edit that file until the
other work is stabilized and integration ownership is explicitly clear.

This target may proceed with new platform-web files, static-shell files,
documentation, and their tests. Existing dirty drafting, model, edit-engine,
render, e2e, and visual-reference paths are read-only.

## Expected work

1. Define a browser IndexedDB recovery store with per-project records,
   validation-on-read, bounded retention, and failure reporting.
2. Define an optional File System Access adapter without making it a required
   Page capability.
3. Make Vite/manifest/service-worker paths base-aware and remove the unsafe
   cache-all GET strategy.
4. Correct documentation to schema v2 and distinguish formal project files,
   imported SPICE, browser recovery, and PWA cache.
5. After the dirty editor target is integrated, make a follow-on integration
   plan to replace the single localStorage recovery slot and wire UI save
   states to these adapters.

## Commit intent

Commit only the independent Page platform foundation. Editor lifecycle wiring
is deliberately a separate commit after the overlapping `App.tsx` work is
coordinated.

## Progress and validation (2026-08-09)

Implemented the independent foundation:

- `@icm/platform-web` supplies a validated, per-Project IndexedDB recovery
  envelope and a structural optional File System Access adapter.
- The editor build is base-path aware through `ICM_PAGE_BASE_PATH`; the
  manifest uses relative PWA paths; the service worker no longer caches every
  GET request, skips forced takeover, or treats cache storage as Project data.
- The canonical Project and recovery specifications now describe schema v2 and
  the Page v1 source/recovery boundaries.

Validation passed:

- `pnpm exec vitest run packages/platform-web/src/browser-recovery.test.ts packages/platform-web/src/file-system-access.test.ts` (6 tests)
- `pnpm --filter @icm/platform-web build`
- `ICM_PAGE_BASE_PATH=interactive-circuit-maker pnpm --filter @icm/editor build`
- `git diff --check`

The repository-wide typecheck remains blocked by pre-existing dirty symbol
